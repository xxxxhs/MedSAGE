# MedSAGE: Reproducibility Materials and Per-Question Evaluation Results

This repository contains the implementation and reproducibility materials for the manuscript:

**Improving Medical Question Answering in Online Health Consultations Through Retrieval-Augmented Semantic Aggregation of Multiple Physician Responses**

The repository includes the released MedSAGE implementation, experiment configurations, question-level generated outputs, and corresponding automatic evaluation scores for the quantitative results reported in Tables 1 and 4–8 of the manuscript.

---

## 1. Reproducibility Update

This repository was updated in response to the editorial request for additional clarification and question-level reproducibility materials.

The current release provides:

- the finalized MedSAGE implementation;
- question-level generated outputs;
- question-level automatic metric scores;
- experiment-condition labels corresponding to Tables 1 and 4–8;
- documentation describing the relationship between the released files and the manuscript results.

The released question-level files allow the aggregate values reported in the manuscript tables to be reproduced by grouping the records according to model and experimental condition and averaging the corresponding automatic metric scores.

## 2. Clarification of the Centrality Calculation

The finalized MedSAGE implementation constructs a binary semantic graph among candidate evidence sentences.

For candidate sentences \(s_i\) and \(s_j\), an edge is created when their cosine similarity exceeds the semantic similarity threshold \(\tau\).

The centrality score is therefore computed as the binary node degree:

```python
adj = (similarity_matrix >= tau).astype("float32")
np.fill_diagonal(adj, 0)
centrality = adj.sum(axis=1)
```

Because the graph is binary, the raw degree-centrality value is integer-valued.

Before score aggregation, centrality, relevance, and diversity are independently normalized within each candidate set using min-max normalization:

```text
C_norm = minmax(C)
R_norm = minmax(R)
D_norm = minmax(D)
```

The final sentence-ranking score is then computed as:

```text
Score = wC * C_norm + wR * R_norm + wD * D_norm
```

The default aggregation coefficients are:

```text
C : R : D = 1 : 1 : 1
```

The default semantic similarity threshold is:

```text
tau = 0.7
```

and the default number of selected evidence sentences is:

```text
K = 10
```

## 3. Clarification of the Previous Table S5

The non-integer centrality values shown in the previous version of Supplementary Table S5, such as `25.5051`, originated from an early prototype used during method development.

That early result was retained only as an illustrative worked example intended to demonstrate the intermediate scoring process. It was not generated by the finalized implementation used for the quantitative experiments.

The obsolete illustrative result was inadvertently retained in the supplementary material during an earlier revision.

Importantly, the values in the previous Table S5 were **not used to generate the quantitative results reported in Tables 1 or 4–8**.

All quantitative results reported in Tables 1 and 4–8 were produced using the finalized implementation released in this repository, which uses:

1. binary degree centrality;
2. candidate-level min-max normalization;
3. normalized weighted aggregation of centrality, relevance, and diversity.

No algorithmic change was introduced to generate the reported main experimental results during the revision process.

```text
results/
```

Each JSONL file contains one JSON object per model output under a specific experimental condition.

Original cMedQA2 question identifiers are replaced by stable anonymized `sample_id` values in the public release.

The same anonymized `sample_id` is retained across experimental conditions when the same evaluation question is used, enabling paired comparison between methods.

## 12. Automatic Evaluation

Generated responses were evaluated using the automatic metrics reported in the manuscript, including:

```text
BLEU-2
ROUGE-L
METEOR
CIDEr
BERTScore-F1
```

For each evaluated question, the generated answer was compared against the available physician reference answers associated with that question.

Question-level metric scores are stored directly in the released JSONL files.

The manuscript table values are obtained by averaging the corresponding question-level scores for each experimental condition.

For analyses in which a metric was not reported in the corresponding manuscript table, that metric is not required in the released file.

## 13. Data Identifiers

To avoid redistributing original dataset identifiers unnecessarily, publicly released result files use anonymized identifiers of the form:

```text
S_xxxxxxxxxxxx
```

These identifiers are stable across experimental conditions for the same evaluation question.

The mapping between the anonymized identifier and the internal dataset identifier is not required for reproducing aggregate metric calculations from the released question-level results.

## 14. Code and Result Consistency

The implementation currently released in this repository is the implementation used for the reported main experiments.

In particular:

- semantic graph edges are binary;
- centrality is binary node degree;
- centrality, relevance, and diversity are independently min-max normalized;
- normalized component scores are combined using the specified C/R/D coefficients;
- the default semantic threshold is `tau=0.7`;
- the default evidence size is `K=10`;
- the default coefficient setting is `C:R:D=1:1:1`.

The main quantitative results reported in Tables 1 and 4–8 were generated using this finalized implementation.
